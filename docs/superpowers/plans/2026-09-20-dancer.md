# Dancer — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Entregar editor estático Astro de danças Habbo, usando wsproom, com publicação no GitHub Pages.

**Architecture:** Astro gera a página e carrega TypeScript do editor no navegador. Um adaptador wsproom compartilha o frame ativo com a interface; ferramentas Node preparam e validam os assets antes do build.

**Tech Stack:** AstroJS, TypeScript, PixiJS, WiredSnippets/wsproom, testes unitários e navegador, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-20-dancer-design.md`

## Restrições globais

- Build estático; nenhum endpoint de servidor ou proxy em produção.
- Assets baixados em `public/assets/shroom/` e temporários em `.cache/shroom/`, ambos ignorados pelo Git.
- Assets obrigatórios e validados antes de qualquer build, inclusive `astro build` direto.
- API `https://www.habbo.[hotel]/api/public/users?name=<nick>` no navegador.
- Interface branca, mínima, em português; editor e prévia lado a lado.
- Quarto 3×3 sem paredes, avatar central e rotacionável.
- Commits progressivos após verificações de cada etapa; não commitar downloads.

## Pontos de revisão

1. Publicação sob `/dancer/`: nenhum fetch pode escapar do base path.
2. Cache incompleto: diretório existente não implica assets válidos.
3. Trocas rápidas de avatar: resposta antiga não pode sobrescrever escolha nova.
4. XML e SHROOM inválidos: preservar o documento anterior.
5. Pausa e edição: frame visível deve coincidir com o selecionado, inclusive após mudança de direção.

## Execução e verificação

Plano aprovado pelo usuário e executado diretamente nesta sessão, com commits progressivos e revisão independente ao final. As etapas 3 e 4 foram registradas juntas por compartilharem o fluxo de prévia. O resultado local contém workflow de publicação; nenhum remoto foi configurado ou publicado.

Evidências: 16 testes unitários, typecheck, quatro testes de navegador; build estático com 3.013 arquivos de assets validados. O teste de navegador cobre edição com comparação de pixels, pausa/seek, quatro presets, oito direções, XML exportado e reimportado, persistência, importação inválida, consulta ao hotel e viewport móvel. A API brasileira também foi consultada sem interceptação no navegador. O build sem assets falhou no hook obrigatório. `git ls-files public/assets/shroom .cache/shroom` retorna vazio.

Decisões de integração: usar ESM do wsproom para compartilhar uma única instância de PixiJS; converter o índice XML para duas unidades internas do motor; remover referências órfãs de manifests apenas quando também ausentes dos símbolos do SWF original. O adaptador permanece fixado na versão do motor testada.
